Descripción detallada

Driver para sensor PIR (Passive Infrared) de detección de movimiento.

Autor
Jair Hernan Telpis Cuaran, Luis Fernando Gamba Bedoya
Fecha
2025
Versión
1.0

Este módulo proporciona driver para sensores PIR HC-SR501 o compatibles. El sensor detecta movimiento mediante cambios en la radiación infrarroja.

Hardware:

  • Sensor PIR HC-SR501 (o compatible)
  • Pin OUT conectado a GPIO 35 (configurable)
  • VCC: 5V, GND: GND
  • Salida digital: HIGH cuando detecta movimiento

Modos de operación:

  1. Polling: Llamar pir_is_motion_active() periódicamente
  2. Interrupt: Pasar una cola a pir_init() para recibir eventos

Configuración del sensor HC-SR501:

  • Delay time: Ajusta cuánto tiempo permanece HIGH después de detección
  • Sensitivity: Ajusta el rango de detección (3-7 metros típico)
  • Trigger mode: Repeatable (H) o Non-repeatable (L)
Nota
Este driver soporta tanto ISR como polling

◆ pir_init()

void pir_init ( gpio_num_t pir_gpio,
QueueHandle_t pir_queue )

Inicializa el sensor PIR con ISR o polling.

Configura el GPIO como entrada y opcionalmente registra una ISR para detectar cambios automáticamente.

Configuración del GPIO:

  • Modo: INPUT
  • Pull-up: Deshabilitado (sensor tiene pull-up interno)
  • Pull-down: Deshabilitado
  • Interrupción: Ambos flancos (ANYEDGE) para detectar inicio y fin

Con cola (modo interrupt):

  • Cada cambio en el pin dispara ISR
  • ISR envía evento a la cola
  • Tarea puede esperar en xQueueReceive()

Sin cola (modo polling):

  • Pasar NULL como pir_queue
  • Llamar pir_is_motion_active() periódicamente
Parámetros
[in]pir_gpioPin GPIO donde está conectado el sensor (ej: GPIO_NUM_35)
[in]pir_queueCola para eventos (puede ser NULL para modo polling)
Atención
Llamar solo una vez durante inicialización
Si se usa cola, crearla antes con xQueueCreate()
Nota
Instala servicio ISR global si aún no está instalado

pir_is_motion_active() Para lectura directa sin cola

Inicializa el sensor PIR con ISR o polling.

Secuencia de inicialización:

  1. Guarda parámetros en variables estáticas
  2. Configura GPIO como entrada sin pull-up/down
  3. Habilita interrupción en ambos flancos (ANYEDGE)
  4. Instala servicio ISR global (si no existe)
  5. Registra handler específico para este pin

Configuración GPIO:

  • Modo INPUT: Lee nivel lógico del sensor
  • Sin pull-up/down: Sensor tiene electrónica interna
  • ANYEDGE: Detecta inicio (LOW→HIGH) y fin (HIGH→LOW)

Alternativa solo subida: Cambiar a GPIO_INTR_POSEDGE para solo notificar inicio de movimiento.

Parámetros
[in]pir_gpioPin GPIO (ej: GPIO_NUM_35)
[in]pir_queueCola FreeRTOS o NULL para modo polling

◆ pir_is_motion_active()

bool pir_is_motion_active ( void )

Lee el estado actual del sensor PIR (polling).

Lee directamente el nivel lógico del GPIO configurado. Útil para modo polling sin necesidad de ISR/cola.

Interpretación:

  • true (HIGH): Sensor detecta movimiento ahora
  • false (LOW): No hay movimiento detectado

Uso recomendado: Llamar desde tarea periódica (cada 1-2 segundos) en modo polling, o desde sensor_task para centralización thread-safe.

Devuelve
bool Estado del sensor
Valores devueltos
trueMovimiento detectado (pin en HIGH)
falseSin movimiento (pin en LOW)
falseSi el sensor no ha sido inicializado
Nota
Thread-safe: solo lectura de GPIO
Tiempo de ejecución: <1μs

sensor_task.c Integración con sistema de sensores

Lee el estado actual del sensor PIR (polling).

Lee directamente el nivel del GPIO sin usar interrupciones.

Proceso:

  1. Verifica que el GPIO esté inicializado
  2. Lee nivel con gpio_get_level()
  3. Retorna true si nivel es HIGH (1)

Seguridad: Si el sensor no se inicializó, retorna false para evitar lecturas erróneas.

bool Estado actual del sensor
Valores devueltos
trueMovimiento detectado (GPIO HIGH)
falseSin movimiento o sensor no inicializado
